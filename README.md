# Music Player

Учебный Android-проект локального музыкального плеера. Приложение выбирает аудиофайлы через Storage Access Framework (SAF), читает метаданные, сохраняет плейлист между запусками, позволяет удалять отдельные записи и воспроизводит треки через ExoPlayer 2.19.1.

## Возможности

- Импорт одного или нескольких аудиофайлов через SAF (`ACTION_OPEN_DOCUMENT`, тип `audio/*`) с получением постоянного разрешения на чтение.
- Отображение названия, исполнителя, длительности и встроенной обложки. Для отсутствующих названия и исполнителя показываются `Unknown Track` и `Unknown Artist`.
- Удаление отдельной композиции кнопкой-корзиной в её строке. Удаляется только запись из плейлиста и сохранённых данных; исходный аудиофайл на устройстве остаётся нетронутым. Изменения сохраняются для последующих запусков приложения. Кнопка удаления доступна только в списке, на экране проигрывания её нет.
- При удалении не текущей композиции текущая не прерывается: играющая продолжает воспроизводиться с прежней позицией, приостановленная остаётся на паузе. При удалении текущей композиции воспроизведение останавливается, а следующая автоматически не запускается. Оставшиеся композиции сохраняют порядок; после удаления последней записи плейлист становится пустым.
- Список треков на `RecyclerView`: обложка или placeholder, название, исполнитель, длительность, индикатор состояния Play/Pause и кнопка удаления.
- Управление воспроизведением из строки плейлиста: нажатие на обложку или значок Play/Pause запускает трек, ставит его на паузу и снимает с паузы, не открывая отдельный экран.
- Отдельный экран проигрывания открывается нажатием на строку композиции. На нём отображаются крупная обложка, название, исполнитель, прошедшее и общее время, кнопка Play/Pause и кнопка возврата к списку.
- Нажатие на другую композицию делает её текущей и запускает воспроизведение. Повторное открытие экрана текущей композиции не прерывает воспроизведение и не сбрасывает паузу.
- Прогресс воспроизведения показывается в строке текущего трека (после первого запуска) и на отдельном экране проигрывания.
- Перемотка текущей композиции через `SeekBar` на экране проигрывания. При неизвестной или нулевой длительности перемотка отключается.
- Автоматический переход к следующей композиции после завершения текущей.
- После завершения последней композиции воспроизведение останавливается: используется `REPEAT_MODE_OFF`, циклического повтора плейлиста нет.
- Повторное нажатие Play на завершившейся композиции запускает её с начала — как в строке плейлиста, так и на экране проигрывания.
- Сохранение плейлиста в `SharedPreferences` в виде JSON-массива URI и восстановление при следующем запуске.
- Автоматическая миграция старого формата хранения, где URI были разделены строкой `", "`.
- Плейлист и текущее состояние плеера переживают поворот экрана благодаря `ViewModel`.
- Светлая и тёмная темы (Material 3 DayNight), edge-to-edge с обработкой системных insets.

## Ограничения текущей версии

- Нет `MediaSession`, foreground service и уведомления с управлением воспроизведением. После завершения процесса плейлист восстанавливается, но текущий трек и позиция воспроизведения — нет.
- Нет переупорядочивания треков, поиска и отдельных кнопок «предыдущий/следующий». Перемотка работает только внутри текущей композиции.
- Используется устаревшая библиотека ExoPlayer 2.19.1; переход на Media3 не выполнялся.
- Дедупликация выполняется по URI. Один и тот же файл, представленный провайдером разными URI, может добавиться повторно.

## Технологии

- Kotlin 2.2.10, Gradle 9.6.0 (wrapper), Android Gradle Plugin 9.5.0.
- `compileSdk`/`targetSdk` 36, `minSdk` 21 (Android 5.0), Java source/target 11.
- ExoPlayer 2.19.1 (`com.google.android.exoplayer:exoplayer-core`).
- AndroidX: AppCompat, Material 3, RecyclerView, ConstraintLayout, Fragment, Lifecycle ViewModel KTX, Preference KTX, Core KTX, Annotation.
- Kotlin Coroutines для чтения метаданных и разбора сохранённого плейлиста вне главного потока.
- `SharedPreferences` и `org.json.JSONArray` для хранения плейлиста.
- Storage Access Framework и persistable URI permissions для доступа к выбранным файлам.
- XML-разметка и `findViewById`; viewBinding, dataBinding и DI-фреймворки не используются.
- Версии зависимостей заданы в `gradle/libs.versions.toml`.

## Структура проекта

```text
app/src/main/java/com/example/musicplayer/
├── domain/
│   └── PlaylistManager.kt      # интерфейс плейлиста, Item и Listener
├── data/
│   ├── PlaylistManagerImpl.kt  # метаданные, состояние треков, удаление, сохранение
│   └── PlaylistStorage.kt      # JSON-формат и миграция старого формата
└── ui/
    ├── main/
    │   └── MainActivity.kt     # edge-to-edge, обработка WindowInsets
    ├── nowplaying/
    │   └── NowPlayingFragment.kt # экран проигрывания, время, SeekBar, Play/Pause
    └── playlist/
        ├── PlaylistFragment.kt  # экран плейлиста и выбор файлов через SAF
        ├── PlaylistViewModel.kt # PlaylistManager и ExoPlayer, переживают поворот
        ├── PlaylistAdapter.kt   # RecyclerView, строка трека и кнопка удаления
        └── PlaybackProgress.kt  # снимок прогресса, форматирование времени и пересчёт после удаления
```

Разметка, строки, цвета и темы находятся в `app/src/main/res/`.

Слои `domain`, `data` и `ui` разделены по назначению, но `domain` не является полностью независимым от Android: интерфейс использует `Uri`, `Bitmap` и `SharedPreferences`. Это учебная слоистая структура, а не строгая Clean Architecture.

## Требования

- Android Studio актуальной стабильной версии с поддержкой Android Gradle Plugin 9.5.0 и Gradle 9.6.0.
- JDK 21 — конфигурация, на которой проверена сборка проекта. При необходимости укажите путь к JDK через переменную `JAVA_HOME`.
- Android SDK Platform 36.
- Эмулятор или устройство с Android 5.0 (API 21) и выше. Для проверки воспроизведения нужны аудиофайлы, доступные через системный файловый провайдер.

## Сборка и запуск

Команды выполняются из корня проекта в PowerShell:

```powershell
$env:JAVA_HOME="<путь к JDK 21>"
.\gradlew.bat assembleDebug
```

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`.

Запуск из Android Studio:

1. Откройте корневую папку проекта.
2. Дождитесь синхронизации Gradle.
3. Выберите эмулятор или подключённое устройство и нажмите Run.

Установка собранного APK через `adb`:

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## Использование

1. Запустите приложение. При пустом плейлисте отображается приглашение добавить треки.
2. Нажмите кнопку «+» и выберите один или несколько аудиофайлов.
3. После чтения метаданных треки появятся в списке.
4. Нажмите на обложку или значок Play/Pause в строке трека: воспроизведение начнётся, при повторном нажатии поставится пауза, затем воспроизведение продолжится. Отдельный экран при этом не открывается.
5. Нажмите на название, исполнителя или свободную область строки — откроется экран проигрывания с обложкой, названием, исполнителем и временем. Выбор другой композиции в списке запускает её; открытие экрана уже играющей или приостановленной композиции не меняет состояние воспроизведения.
6. На экране проигрывания управляйте воспроизведением кнопкой Play/Pause и перематывайте текущую композицию перетаскиванием ползунка `SeekBar`.
7. После завершения трека автоматически запускается следующий. После завершения последнего трека воспроизведение останавливается и плейлист не повторяется; нажмите Play, чтобы запустить завершившуюся композицию с начала.
8. Чтобы удалить композицию, нажмите кнопку-корзину в её строке. Удаляется только запись из плейлиста приложения, файл на устройстве остаётся. При удалении другой композиции текущая не прерывается и сохраняет позицию: играющая продолжает играть, приостановленная остаётся на паузе. При удалении текущей воспроизведение останавливается, а следующая автоматически не запускается. После удаления последней записи отображается пустой плейлист; файл можно снова добавить через кнопку «+» и SAF.
9. Закройте и снова откройте приложение — сохранённый плейлист восстановится.

## Хранение плейлиста

- Плейлист хранится в `SharedPreferences` под ключом `KEY_PLAYLIST` в виде JSON-массива строк с URI.
- При чтении пустые значения и дубликаты URI удаляются, исходный порядок сохраняется.
- Если обнаружен старый формат `", "`, он автоматически преобразуется в JSON после успешного восстановления треков.
- Файл плейлиста исключён из облачного резервного копирования и переноса между устройствами: persisted URI permissions не переносятся вместе с ним.

## Тесты и проверки

```powershell
.\gradlew.bat testDebugUnitTest
.\gradlew.bat connectedDebugAndroidTest
.\gradlew.bat lint
```

- `testDebugUnitTest` запускает локальные unit-тесты: `ExampleUnitTest` и `PlaybackProgressTest` (форматирование времени, расчёт прогресса, цель перемотки и пересчёт индекса прогресса после удаления).
- `connectedDebugAndroidTest` требует подключённого эмулятора или устройства. Проверяет хранение, восстановление и удаление плейлиста (`PlaylistStorageTest`, `PlaylistManagerImplTest`, `PlaylistViewModelTest`), интерфейс и навигацию (`PlaylistFragmentUiTest`, `PlaylistInteractionTest`, `PlaylistProgressUiTest`, `NowPlayingFragmentTest`), обработку insets (`MainActivityInsetsTest`), а также содержит `ExampleInstrumentedTest`.
- `lint` формирует отчёт в `app/build/reports/lint-results-debug.html`.

Инструментальные тесты проверяют выбор и воспроизведение треков, разделение Play/Pause и открытия экрана, отображение прогресса, перемотку, автоматический переход, повторный запуск завершившейся композиции, удаление текущей и не текущей композиции, сохранение порядка и пустое состояние после удаления последней записи. Реальное звучание и работа с конкретными SAF-провайдерами ими не проверяются.
